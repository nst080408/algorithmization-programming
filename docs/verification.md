# Проверка расчёта функции

Проверено 17.11.2026. Решение собрано на .NET SDK 10.0.404 в конфигурации Release: 0 предупреждений, 0 ошибок.

Ввод выполняется через `double.Parse(input)`, как в учебном примере. Отдельно проверены русские настройки `ru-RU` с запятой и английские `en-US` с точкой. Настройки менялись только в проверочной программе; в исходном коде учебных проектов настройки культуры не задаются.

Для каждого набора выполнен отдельный запуск. Ответы сравнены с независимым расчётом с 50 значащими цифрами. Допуск: максимум из `10⁻¹²` и `10⁻¹⁴` от модуля эталона. Все проверки прошли.

В [verification.xlsx](verification.xlsx) сохранён расчёт в Excel. При `x = 2` результат составляет `2,7338095116624275`. В файле `C13` содержит числитель, `C14` знаменатель, `C15` их частное.

Формулы Excel: `C13 = C7*C10^2+(3/5)*C8*ABS(C10)`, `C14 = C9+SQRT(C10^2+4)`, `C15 = C13/C14`. В `C7:C10` заданы a = 3, b = 1, c = 2, x = 2.

Текст контрольного запуска сохранён в [console-example.txt](console-example.txt). Ввод при проверке перенаправлялся в программу, поэтому введённая цифра не повторяется в журнале.

Программа предполагает корректный ввод. Пустая строка, текст и неподходящий десятичный разделитель не обрабатываются. Вывод выполняется без специального округления.
