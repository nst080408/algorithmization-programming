# Оформление работы на GitHub

Порядок основан на разделах 1 и 2 методички. Этот файл описывает действия; он не означает, что issue и pull request уже созданы.

## Репозиторий

В методичке предлагается один репозиторий на весь семестр. Например, его можно назвать `algorithmization-programming`. В описание репозитория нужно вписать настоящие ФИО, группу и год. Эти сведения в файлы не добавлены, потому что они не были предоставлены.

Не загружать `.vs`, `bin`, `obj` и чужую папку `.git`. В архиве оставлены исходники и документы; служебные файлы исключены.

## Начальная версия

Если репозиторий создаётся с нуля, сначала добавить `.gitignore`, `.gitattributes` и заготовку решения. Для заготовки можно создать по инструкции методички решение `Task 1` и консольный проект `Task 1-1` с обычным `Hello, World!`. Готовый `Program.cs` из этой работы добавить уже в рабочую ветку после создания issue.

Так начальная версия и выполненное задание будут действительно различаться, а pull request покажет добавленный расчёт.

## Issue

Создать issue с заголовком **«Решить задание 1.1. Вариант 11»**. Готовый текст находится в [task-1-1-issue.md](task-1-1-issue.md). Назначить себя исполнителем.

После создания issue использовать его настоящий номер в имени ветки. Например, если GitHub присвоил issue номер 1, создать ветку `feature/1`. Номер issue и номер варианта не обязательно совпадают.

В методичке также описано приглашение преподавателя `MarinaPaley` в сотрудники репозитория. Приглашение отправляется владельцем аккаунта по правилам учебного курса.

## Рабочая ветка

В рабочую ветку добавить готовый `Program.cs`, документы из `docs` и обновлённый `README.md`. В решении сохранить имя проекта `Task 1-1` и целевую платформу .NET 10.0.

Перед коммитом запустить программу с `x = 2` и проверить результат. Подходящее сообщение коммита:

```text
Выполнено задание 1.1: расчёт функции для варианта 11
```

Если ввод, расчёт и документация добавляются раздельно, для этих реальных изменений можно делать отдельные коммиты. Не нужно создавать пустые коммиты или придумывать историю работы.

## Pull request

Отправить рабочую ветку на GitHub и открыть pull request в главную ветку. Заголовок: **«Выполнено задание 1.1. Вариант 11»**. Описание подготовлено в [task-1-1-pr.md](task-1-1-pr.md).

Связать PR с issue через **Development** или добавить в описание `Closes #N`, заменив `N` настоящим номером issue. Назначить преподавателя рецензентом, если приглашение уже принято и это требуется для сдачи.

По методичке слияние выполняется после одобрения преподавателя. Затем можно удалить рабочую ветку и обновить локальную главную ветку.
